## Legend

**effect**

- `read`: Changes nothing itself. eval.run and plan.run carry this effect but can run writes: eval.run can run any Python (it is off unless FLAME_MCP_ENABLE_EVAL=1), plan.run through its steps.
- `reversible`: Changes something that already exists.
- `create`: Creates something new: an object in the project, a file or a render's output.
- `destructive`: Deletes or replaces something that exists.

**undo**

- `none`: No undo: journal.revert has nothing in the project to put back.
- `value`: journal.revert puts the previous value back, deletes what the call made, or puts the thing back where it was.
- `checkpoint`: journal.revert restores the checkpoint taken before this call.
- `unsupported`: This operation cannot be undone: journal.revert does not reverse it.

† Gated by the default policy; see [Gated operations](#gated-operations).

## Gated operations

- `eval.run` is registered with effect `read`. Under the default policy it is not listed and every call is denied, whatever effect the call declares: operation 'eval.run' is disabled on this server. eval.run runs any Python with the permissions of the user running Flame. Set FLAME_MCP_ENABLE_EVAL=1 to enable it, or use a dedicated operation from flame_catalog.
